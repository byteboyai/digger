## 执行规则

- 首先读取执行时适用工作指令，记录当前 HEAD/status；本次规划基线为 `8788b56`，原有 dirty Cargo.lock 保留。个人 `.cargo` 配置不删除/提交；开发验证与正式无 patch 验证分别记录。
- 所有路径相对于 Digger；兄弟库只作已有能力核对。共享 API 无必要不修改、不为空发 tag；本计划不要求修改 Dozer 产品。
- 按行为/存储/宿主/产物形成可审阅变更；不依靠破坏原项目数据做故障测试。复制、迁移、恢复均用临时工程和保留原件的 fixture。
- 先写能证明用户结果的回归，再实施；协议/权威状态变更必须同步 Rust、TS、fixture、bundle。纯代码搬移不另写镜像测试。
- 实施顺序：T0 → T1 → T2 → T3 → T4 → T5 → T6 → T7 → T8。同一阶段内允许按实际依赖调整，但不能在切换/退出之前遗漏 flush 与持久化确认。
- 本轮只写规划，不执行实现或推送。后续提交、CI、共享发版和产品发布按执行时授权与仓库流程处理，记录实际结果。

- [x] 明确 ADR-003 的文稿最小事务 schema 与 coordinator：哪些表落地、哪些通用治理能力仍延期；保留原子性/幂等/CAS/Outbox 不变量。
- [x] 固化首次导入、重复路径、项目副本/移动、库替换、未来 schema、备份恢复与旧产品只读规则；新 schema 不声称可由旧二进制写入。

## T1：文稿仓库、版本与保存事务

**文件：** `crates/store/src/writing/`（新增模块）、`crates/store/src/lib.rs`、`crates/editor/src/doc.rs` 的纯快照校验/序列化接缝；必要的 Cargo 依赖声明。

- [x] 建立版本化 migration、Document/Version/Commit/revision/Outbox/幂等记录，域类型与错误采用 typed 接口，不向 desktop 暴露 Connection。
- [x] 新建/导入在事务中分配稳定 ID 和路径；重复导入返回已有文档或明确候选，不产生无意的副本/覆盖。
- [x] 实现 Save(expected revision, operation ID, immutable snapshot)，原子提交正文和所有不可重建块状态。
- [x] 验证 Doc identity state 与正文匹配；产品存储损坏不得走 `import_state` 的宽松回退重新分配 ID 后伪称正常恢复。
- [x] 明确 export_state pending history 的所有权：失败重试、边保存边输入、幂等重放不丢失/重复确认 history。
- [x] 有界后台 IO 与版本冲突/只读/存储损坏/超限等结构化错误落地。
- [x] 测试事务各阶段异常、真实进程崩溃、提交后回复丢失、相同/不同指纹幂等、双进程 CAS 竞争和新旧 schema。

**验证：** `cargo test --locked -p digger-store`、纯 editor 状态 round-trip/协议测试；临时库重开检查真实事务事实。
**退出：** A2/A3 的存储部分；没有 UI 也能证明原子性及块身份跨重启。

## T2：恢复草稿与可恢复镜像 worker

**文件：** `crates/store/src/writing/{recovery,mirror,...}.rs`（按实际拆分）；复用既有共享 file-io。

- [x] Recovery 实现带 base/session/buffer 水位的校验与原子文件写入；损坏/未来 schema 保留原件并返回可处理结果。
- [x] 实现读取分类：可恢复、已提交冗余、基版本落后、损坏、不支持；恢复不能自动覆盖 Official State。
- [x] Outbox worker 按文档协调 revision，提交之后写镜像；持久化状态/重试/队列和退出策略有明确所有者（不因外部冲突阻止退出；Outbox 保留待重放）。
- [x] 文件写入前核对身份、revision 和期望镜像摘要；拒绝项目外链接/路径及内部目录；编码、换行/BOM 和元数据规则实现。
- [x] 检测外部修改并暂停自动覆盖；保存外部候选/快照基线，处理显式覆盖确认过期；不自动三方合并。
- [x] 崩溃点覆盖：DB 已提交但未镜像、临时文件未 rename、已 rename 未确认、恢复重放时外部文件又变化、旧 revision 任务迟到。
- [x] 测试磁盘/权限/队列失败、文件增长/替换、符号/硬链接路径别名及重复镜像目标，原件不得被静默覆盖。

**退出：** A6–A8 后台部分可独立验证；镜像失败不冒充数据库未保存，外部变化不丢失。

## T3：编辑会话与 flush/save/recovery 状态机

**文件：** `crates/desktop/src/markdown/`、`crates/editor/src/{bridge,protocol,doc}.rs`、`crates/desktop/web/src/{rust-sync,cm-engine,app}.ts`、相关 fixture。

- [x] 引入活动 store/document/session 身份和文稿加载状态；Bridge 从校验后的 saved state 构造，不再在正常模式固定 SAMPLE。
- [x] 让 load、页面 open/ACK、保存和恢复回包带身份；失效旧 epoch，拒绝旧结果影响新文档，保留已准入提交的结算。
- [x] 实现带 request ID 的 flush 屏障，覆盖 sent/queued、IME、握手未完成、重复/旧 ACK；超时保留原会话。
- [x] 保存截取明确的 buffer 快照；成功确认对应 durable 水位，后续输入继续显示未保存；UI 不执行 IO。
- [x] 自动草稿按 500ms 静默/2s 连续输入节奏合并写入，有界；按当前文稿/操作编号隔离回包，写入失败可见。可控时钟覆盖 500ms/2s 调度，恢复预览显示基版本。
- [x] 切换/关闭统一使用“保存/保留恢复草稿/取消”协调，明确丢弃与强退语义；失败时不切走丢内容。
- [x] 正常模式移除 StandIn 产品按钮，SelfTest 保留可独立的内存 fixture；已有 harness 仍测生产同步路径，新增持久化场景不依赖用户项目。
- [x] 测试 A/B 文档/项目乱序、旧失败、Retry、加载失败、保存中继续输入及恢复基版本前进（无窗口状态/消息回归；实机组合仍在 T6）。

**退出：** A4/A5 的纯状态和协议证据完整，撤销/主题/增量回归保持通过。

## T5：端到端持久化与故障回归

- [x] 临时真实项目通过消息驱动执行新建/导入→编辑→保存→镜像→关闭/重开，逐字段检查正文、文稿 ID、块 ID/aliases/history 和 revision；正常 GUI 退出/重启仍在 T6。
- [x] 覆盖两个项目、两个文稿、同路径重开/库替换、可控后台阻塞下的慢 save/load、窗口关闭后的已准入提交，不污染新 UI 状态（无窗口生产消息路径；真实窗口验收在 T6）。
- [x] 领域与生产消息路径覆盖未确认页面输入、恢复重放/损坏、存储损坏/只读、外部编辑及确认过期；新增 SQLite 拒写后再输入/重试、损坏目标保留源缓冲、过期外部确认后重新预览/另存副本。实机可操作性在 T6。
- [x] 真子进程 failpoint 与磁盘断点检查“提交前不变、提交后可重放”，保留原数据库/源文件摘要作为证据。
- [x] 核对嵌入 web dist，运行 Rust editor、TS 同步测试、parser fixtures 和嵌入产物一致性检查；本轮协议/TS 无新增修改。完整随机属性矩阵保留 CI/slow 验证范围。

**退出：** A1–A8 有跨层证据；不借用旧账本/项目迁移测试代替文稿回归。

## W2–W5 后续任务队列
