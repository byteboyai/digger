## 0. 先读这个

**不要动 `/Applications` 里正在运行的应用。** 用开发构建,并且 Digger 用独立数据目录,避免碰到你日常用的数据和 `diggerd`:

```bash
# Digger(独立数据目录 + 独立 daemon 套接字,都在这个目录下)
mkdir -p /tmp/digger-accept
DIGGER_DATA_DIR=/tmp/digger-accept cargo run -p digger        # 在 Digger 仓库根目录
```

- **Dozer** 我没有查到类似 `DIGGER_DATA_DIR` 的隔离开关,所以 Dozer 的验收(§G)会用到你日常的 Dozer 数据和 daemon。想避免就用你平时跑开发构建的方式;**如果 Dozer 已在运行,先别在同一台机器上再开一个**。
- **Agent 登录状态:** §B 需要 `claude`、`codex`、`qodercn`、`codebuddy` 至少各登录好一个你想验的;未登录的跳过并记下。
- **准备一个测试项目:** 用一个**可丢弃的 git 仓库**(`git init` 一个小目录并提交一次即可),不要用真实项目;验收中会「删除项目」和「让 agent 只读读文件」。
- 做不出前置条件的项(例如造不出失败)标 ➖「跳过」并写原因,**不要当成通过**。
- 任何一项 ❌,记下现象和截图(如有),不要自己改代码;汇总后再一起处理。
