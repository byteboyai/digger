## Task 1:`digger-mcp` crate

- 新 crate `crates/digger-mcp`:入口只有 `dozer_mcp::server::run_main(digger_paths::product(), McpFeatures { memory: true, 其余 false })`。
- 支持 `serve` / `install <agent>` / `uninstall <agent>`(由共用库分发)。
- `tools/list` 恰为 `write_memory`、`list_memories`、`get_memory`;描述与参数 schema 与 Dozer 同名项共用同一份 `#[tool]` 路由代码。
- 安静模式:无 `DIGGER_SESSION_ID` 但有 `DOZER_SESSION_ID` 时 `initialize` 成功、工具为空、stderr 为空、退出码 0;两者都没有时报 `缺少 DIGGER_SESSION_ID: digger-mcp 只能在 digger 拉起的会话里跑`。
- 端到端测试起一个真实 `dozerd::daemon::run`(产品身份 digger、临时数据根/socket),覆盖写入→列出→按标题读取、同名 upsert、不存在的会话可读报错、MCP 写入经 `ProjectHost` 可见、`updated_by` 为该会话 Agent 的 label、空标题/超长正文。
- `check-host-deps.sh` 的 `HOST_ADAPTER_CRATES` 加入 `digger-mcp`。

## Task 3:自动注册与能力开关

- `DiggerHooks::ensure_mcp`:supported = Claude / Codebuddy / Codex / Opencode / Qodercn;`Aider / Goose / V8agent / Unknown` 空操作。
- 运行同目录的 `digger-mcp install <agent>`:不继承 stdin、丢弃 stdout/stderr、10 秒上限。
- **每个进程每种 Agent 只尝试一次**(D7):成功、退出码 3、失败、超时都记入已尝试集合,不再重试。
- 退出码 3 → 警告「未写入 Digger 的 MCP 条目:<配置文件> 里已有一个名为 "digger" 的服务器」;配置路径用 `dozer_mcp::install::config_path_for_product` 在 Digger 侧重推(不依赖被丢弃的子进程输出)。
- 缺二进制 / 其它退出码 / 超时 → 各一条可读警告;`take_warnings` 取走即清空。
- `AgentCapabilities { mcp_install: true, summary_on_close: false }`;`AgentPanel` 与 `DiggerHooks` 共享警告队列,每次 update 后排空进顶部通知条并 `eprintln!`。
- 会话创建不被安装失败阻塞(测试断言 `create` 仍被调用)。

## Task 4:回合结束刷新 Project 面板记忆

- `ProjectPanel::refresh_memories`:只调库的 `dozer_panel_project::on_activate`(只请求记忆列表),不调 `activate`,因此不补 README、不拉 git、不算磁盘占用。
- `AgentPanel` 不再丢弃 `AgentHostEvent`:按项目排队,`drain_host_events` 交给产品。
- `ProductShell::on_agent_turn_ended`:仅当 Project 面板可见、是当前项目、且该项目面板状态已存在时刷新;`StateChanged` 不刷新。
- 这是相对 Dozer 的有意改进(Agent 写记忆后无需切换面板即可看到)。
