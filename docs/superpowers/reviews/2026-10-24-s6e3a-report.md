## Task 5：预览上下文推送

### 实现

- 新增 `crates/desktop/src/adapters/preview_bridge.rs`：
  - `PreviewBridge::push(project_id, Option<PreviewContext>, delay_ms)`：按项目 nonce 防抖；同项目后一次调用淘汰前一次，不同项目互不淘汰（切项目时旧项目的 `None` 不会被新项目上下文吞掉）。

- `PreviewHub` 记录库排出的 `Effect::ContextChanged { immediate }`，产品侧用 `take_context_push()` 排空。
- `product.rs` 新增 `sync_preview_context(immediate)`：只取**当前项目 Files 面板**的活动页签，调 `dozer_panel_preview::build_preview_context` 后推送；普通变化 250 ms，立即变化 0 ms。
- 启动与守护进程就绪时各补推一次；项目切换时先给旧项目推 `None`，再把当前项目 id 写入轮询用的 `AtomicI64`。

### Task 5 Step 3：`Msg::Preview*` 分支清单

`product.rs` 中实际只有 3 个 `Msg::Preview*` 枚举分支，另有 3 个非消息触达点：

| 位置 | 分支 / 触达点 | 是否触发推送 | 说明 |
|---|---|---|---|
| `product.rs:2018` | `Msg::PreviewEvent(event)` | 不直接触发 | `Ipc` 转成 `Msg::Preview(..., Message::Host(event))`；`BuildFailed` 不推。真正的推送由下游库效果决定。 |
| `product.rs:2046` | `Msg::PreviewCommandsFetched((pid, commands))` | 排空库效果后触发 | 逐条应用 Agent 命令；若库在应用/物化中排出 `ContextChanged`，按它指定的 immediate 推送。命令本身不额外伪造上下文。 |
| `product.rs:2077` | `Msg::Preview(panel, project_id, epoch, message)` | 排空库效果后触发 | 所有页签/宿主事件的主入口。推送时机完全采用库的 `Effect::ContextChanged { immediate }`，不按消息类型猜。 |
| `preview_open()`（非 Msg） | 文件树双击 / Project 文档链接打开 | 是，立即 | 打开新页签后先排空库效果，再显式 `immediate=true`。 |
| `on_current_project_changed()`（非 Msg） | 项目切换 / 关闭最后一个项目 | 是，立即 | 旧项目推 `None`，新项目推实际上下文；无项目时轮询项目 id 归 0。 |
| `on_shell()`（非 Msg） | 预览面板失焦（Files/Project 从可见变不可见） | 是，立即 | 避免 Agent 在上一次 250 ms 防抖窗口里读到旧选区。 |

库侧 `Effect::ContextChanged` 的语义（来自 `dozer-panel-preview`）：

- 切页签、关页签：`immediate=true`；
- 宿主回传的选择区 / 视口 / 模式等变化：`immediate=false`（250 ms）；
- 打开 / 恢复 / 普通更新：按库的 `persist_and_context` 参数（普通为防抖）。

## 已知差异与风险

1. **只保留当前项目预览状态**：Digger 一次只持当前项目的预览页签；后台项目的命令一律立即 `NotFound`（计划已知差异），不会挂起。
2. **命令目标必须是已打开页签**：`Path` 只在 Files/Project 已打开的页签里解析，未打开的文件返回 `NotFound`。因此真机项 2 需先在 Files 面板打开目标文件。
3. **MCP 工具描述仍写“Dozer 预览面板”**：按计划风险 ⑤ 未改 `dozer-mcp`，仅记录。
4. **干净快照的 shared-deps 脚本**：脚本用 `git rev-parse` 找根，`git archive` 不带 `.git`；临时 `git init` 后通过，不影响源码与产物。
5. **退出/杀守护进程**：沙箱中的 `digger` 与 `diggerd` 已停止，临时目录已删除；未触碰 Digger 主工作区、`feat/preview-pairing`、`digger-p4`。
