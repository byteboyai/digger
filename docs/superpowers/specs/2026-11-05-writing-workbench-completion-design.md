## 1. 当前状态与目标

基线：本地 `8788b56`；执行前重新记录 HEAD、工作区状态和共享依赖版本。当前 `MarkdownPanel::new` 加载 `sample.md`，顶栏显示“未持久化 / 示例章节”；正文在 Bridge 内存中，不跟随项目选择切换。文件树/项目链接打开的是预览；Agent 按钮调用 StandIn；`Doc::export_state/import_state` 已具备块身份状态导出/恢复能力，但未接入产品存储。

本规划把原型推进到可持续使用的写作面板。**第一交付里程碑 W1 是：项目内新建/导入文稿 → 编辑 → 保存 → 切换文稿/项目 → 退出重开恢复。** 保存必须包括文本、块身份和版本事实，不能只增加文件写入按钮。

既有编辑协议、增量解析、语法渐显、撤销、主题和创建重试继续复用。原型切片已经完成的内容不重复实施；此前项目数据库、用量账本和清理记录的恢复测试不算文稿保存证据。

## 2. 分阶段范围

| 阶段 | 必须交付 | 阶段完成后可声称 |
|---|---|---|
| W1：真实文稿闭环 | 项目/文档身份；新建与 Markdown 导入；打开与切换；显式保存；恢复草稿；块身份跨重启；安全镜像与外部修改检测；必要实机验收 | 写字台可以保存和恢复真实文稿 |
| W2：日常编辑与组织 | 标题大纲、查找/替换、Source/Live 模式；作品/章节列表与排序；明确的章节移动及路径策略 | 可用于多章节日常写作 |
| W3：Agent 写作闭环 | 文档/块/选区上下文；真实 Agent 改写/追加候选；预览、接受/拒绝、定位、撤销；外部修改三方合并 | Agent 可对真实文稿提交可审阅修改 |
| W4：素材与作品上下文 | 图片粘贴/导入、稳定资源引用、caption/alt/来源；作品约束、章节摘要、术语与引用基础 | 素材和上下文可随作品持久化 |

## 3. 权威数据与模块边界（W1）

### 3.1 项目注册表与文稿存储

- 继续使用 ADR-014 的共享 ProjectInfo、产品独立的 `<config>/projects.db` 注册表；不把书稿塞入注册表、用量库或 Dozer 共享记忆。
- 沿 ADR-012，将当前项目的 Writing Domain 放在 `<project>/.digger/project.db`。项目身份沿用宿主注册表，库内持久化一个独立稳定的 writing-store UUID 用于识别重开/目录替换；不创建与 ProjectInfo 竞争的注册表。不同产品的数据根和进程仍保持独立。
- W1 首次引入 Creator Domain，必须按 ADR-014 的要求复核 ADR-003：保留“正文 + Commit + project revision + Outbox + 幂等结果同事务”的不变量，仅落地文稿需要的最小 coordinator 和 schema。Task 0 记录并更新 ADR 的实际存储映射，不以规划中的通用治理引擎作为 W1 前置实现。
- 打开项目不自动导入所有 Markdown。首次新建/导入才初始化 Writing 库；已有损坏库报错，未来 schema 只读/拒绝写入。不得静默建空库、降级覆盖或以临时内存存储冒充保存。
- 复制工程目录但保留原 writing-store UUID、双实例访问与库文件替换需要检测并有明确处理：不能把不同目录的回包混用。只允许同一文件身份下合作写者通过 revision/CAS 提交；独立副本需独立会话身份，不做跨库同步。

### 3.2 所有权

| 层 | 职责 |
|---|---|
| `digger-editor` | Markdown Doc、块身份、同步协议、保存快照的纯类型/校验；不依赖 SQLite、iced、wry |
| `digger-store` 的 writing 模块 | 文稿仓库、版本/CAS、短事务、幂等提交、Outbox 与恢复记录 IO；不依赖宿主 UI |
| `desktop/markdown` | 单活动编辑会话、页面握手/flush、脏状态、恢复与保存 UI、原生生命周期 |
| ProductShell / 路由 | 项目身份和文稿打开意图、文件树/预览入口、关闭协调；不直接执行 SQL 或文件写入 |
| 后台 worker | 有界 IO、镜像和恢复持久化，结果携带文档/会话身份 |

先沿现有 crate 边界新增 writing 模块；不为 W1 抽独立 markdown-core 仓库、不改 Dozer 文档编辑模型、不重写宿主框架。

## 4. 文稿模型与事务（W1）

### 4.1 最小持久化契约

| 记录 | 必须保留的事实 |
|---|---|
| Document | 稳定 DocumentId（UUIDv7）、标题、项目内相对镜像路径、当前 durable revision、换行/BOM 元信息、时间 |
| DocumentVersion | 正文、完整 Doc identity state、schema、内容摘要、版本与 Commit 关联；历史足够支撑恢复和后续合并 |
| Commit / project revision | actor=Human/Import/Recovery、操作 ID、基版本、结果版本和内容摘要，事务内只递增一次 |
| Outbox | document/revision/path/期望镜像基线/目标摘要、状态和重试信息；与 Commit 同事务插入 |
| 幂等结果 | operation ID + 请求内容指纹 → 原提交结果；同 ID 不同内容拒绝 |
| Recovery | store/document/session、持久基版本、buffer revision、文本和块状态、校验/schema/更新时间；非 Official State |

W1 的具体 SQL 和迁移由 Task 0/1 固化；不得维护两份可独立改写的正文权威。派生块范围可重建，块 ID、next_id、aliases 和尚未提交的 Agent history 不能凭重新 parse 丢弃。

### 4.2 Save 命令

保存输入：`store/document identity + expected durable revision + operation ID + immutable buffer snapshot`。一次短事务校验版本和幂等指纹，提交正文/块状态、Commit、新 revision、镜像 Outbox 与幂等结果；失败则全部不变。

- 编辑缓冲版本、数据库 durable revision、Project revision 分别建模，不能复用为一个计数器。
- 命令准入、事务和排队 IO 在后台，有容量/超时与清晰错误；UI 不执行阻塞 IO。
- 同文档保存按请求顺序协调；保存 r 后继续输入 r+1，r 的成功仅确认该快照，不能将新输入标成已保存。
- 重试同一个 operation ID 不重复提交或生成 Outbox。对外返回“事务结果未知”时，先查幂等结果再决定重试，不能猜测失败。
- `Doc::export_state` 会取走 pending history；实现须明确快照所有权。保存失败保留/归还未提交 history，成功只确认对应快照，不清掉其后的新 history；避免在多个并发快照间重复消费。
- 初期保存完整快照即可，性能有实测瓶颈再压缩；不引入 Rope/CRDT。

## 5. 打开、切换与页面同步（W1）

### 5.1 用户入口

- 无项目：显示“打开项目后新建或导入文稿”，不展示可被误认成真实文件的样例。SelfTest 继续使用独立示例。
- 有项目：提供新建文稿、导入项目内 `.md/.markdown`、选择已导入文稿。新建选择标题/相对路径；目标已存在时引导导入，不覆盖。
- 文件树/预览新增明确“在写字台编辑”动作，W1 保留现有普通打开/双击的预览语义；项目 Markdown 链接也可显式转编辑。未支持类型保留现有路径。
- W1 单活动文档；不要求多文档同时驻留、多窗或跨切换保存 undo 栈。切换后重建该文档的页面投影，当前会话内的输入/Agent 撤销语义不能退化，切换前内容必须已提交或有可恢复草稿。

### 5.2 身份与旧结果

每条 load/save/recovery/mirror/page 回包携带 store UUID、项目路径/库实例身份、DocumentId、session epoch、request ID 和相关 revision。页面原有 generation/nonce 继续校验；同一个页面 generation 不能替代文档 session 身份。

项目切换/关闭、文档切换及 Retry 均明确失效旧投影。旧 A 成功可确认 A 已准入的后台提交事实，但不能改 B 的文字、状态、焦点、错误或“已保存”标签；未准入的旧请求取消。状态所有者持续跟踪已准入写入直到有结论，不因窗口映射丢失而遗失保存结果。

新文档先完成 load 校验，再向页面发带身份的 open；等待握手/打开确认期间禁用可误写旧文档的交互。加载失败保留原文档或显示有明确身份的失败页，不回落样例；Retry 不隐式丢草稿。

### 5.3 保存屏障与脏状态

Rust 已确认的正文未必含页面上仍在 IME、sent/queued 中的最新输入。保存/切换/关闭前先执行带请求身份的 flush 屏障：让页面提交最新缓冲、Rust 确认、页面确认该版本已排空后，才截取可保存状态。IME 正在组合时等待结束并提示，不能通过取消组字完成保存；flush 超时保留原页面和草稿，不丢输入。

页面 ACK 只表示同步完成，不能显示“已保存”。状态至少区分：加载中、未保存、保存中、已保存、保存失败、恢复草稿待处理、版本冲突；镜像另显示待同步/已同步/冲突/失败。顶栏显示当前项目、文稿标题和状态；Cmd/Ctrl-S 触发同一保存路径。

切换/关闭提供保存后继续、保留恢复草稿后继续、取消；主动丢弃须明确指向当前草稿。任何继续都以相应 durable 确认为前提；不可用时留在当前文档并可重试。显式强退可提供，但必须说明尚未持久化的内容不会获得保存保证。

## 6. 恢复草稿（W1）

- 自动保存先定义为 **自动保存恢复草稿**，不把未审阅缓冲自动变成 Official State。初始策略：稳定输入后 500ms 合并写入，连续输入至多 2s 触发一次快照；新编辑继续输入时清楚区分已持久化水位与尚在内存部分。切换/正常退出须强制排空。
- Recovery 落在项目 `.digger/working/`，按文档/会话隔离；校验摘要、写临时文件、sync、原子替换，文件名不能来自未校验用户路径。损坏草稿隔离并可导出，不静默删除或套用。
- 重启先比较 recovery base 与库内版本：相同 base 且有新内容，展示恢复预览；base 已前进则保留为冲突候选，不覆盖当前正文；已提交相同内容的旧 recovery 只在可证明冗余后清理。
- 点击恢复是显式 Recovery Change，经正常 Save 提交；取消不删草稿。只有用户明确丢弃、或对应版本/内容已 durable 后才能清理。
- 磁盘满、队列满、权限失败必须可见，不宣称崩溃前全部输入已经保存。自动草稿不能替代数据库提交与镜像状态。

## 7. Markdown 镜像与外部修改（W1）

- 首次导入保留源文件，校验 UTF-8、大小、BOM/换行；数据库采用 LF，镜像按记录恢复风格，除该明确转换外不规范化无关 Markdown。非法编码/超限返回可读错误，源文件不变。
- 同一库内镜像相对路径唯一；只允许项目根内的常规文件，拒绝 `.digger/`、逃逸路径和指向项目外的链接。大小上限/IO 预算在 Task 0 固化并测试，沿用已发布 file-io 能力；不以 `canonicalize` 一次检查代替写入边界。
- Commit 成功后 worker 原子写镜像；数据库提交不等待镜像成功。镜像失败显示“文稿已保存，文件待同步/同步失败”，可重试。
- 同文档 worker 串行处理 revision；旧任务不能覆盖已同步的新版本。进程重启根据 Outbox 恢复；崩溃发生在文件写成、任务确认之前时，按文件身份/摘要幂等确认，不能再覆盖后续外部修改。
- 导入、打开、保存和重获焦点时重新核对镜像身份/摘要；监听只加速发现，不作为正确性的唯一保证。写镜像使用已发布 `dozer-file-io` 的目录边界、合作锁和 revision 校验；对非合作外部写者的最后竞态明确保证边界，不声称绝对无竞争。
- 外部文件变化立即暂停对应镜像覆盖，保留数据库版本和外部文件/候选：W1 提供查看两份内容、导入为恢复候选、另存副本及取消。显式选择以库版本替换外部文件时绑定已展示的外部 revision，文件再变必须重新确认。
- **W1 不自动三方合并、不做后台自动导入**；保守冲突流程可独立交付。W3 再按 ADR-012 实现有基线历史的三方合并；基线未知始终产生可审阅 WorkingState。

## 8. 验收矩阵（W1）

| 编号 | 必须可验证的用户结果 |
|---|---|
| A1 | 无项目空态；项目内新建/导入真实文稿；现有文件不被覆盖；显式编辑入口可达，普通预览保持可用 |
| A2 | 修改、保存、退出、重开后文本/DocumentId/块身份/next_id/aliases 一致；无关 Markdown 范围不被重写 |
| A3 | 保存事务在任一步失败不出现正文、Commit、revision、Outbox 或幂等结果的部分提交；重复请求只提交一次；跨进程 CAS 争写一方冲突 |
| A4 | 页面 sent/queued、中文 IME、边保存边输入的快照水位正确；ACK 不假冒保存，超时/失败保留输入和重试入口 |
| A5 | 真实项目/文档消息路径下 A→B、隐藏切换、关闭重开、同路径新库、迟到 load/save/失败均不串文稿；已准入 A 提交仍可正确结算 |
| A6 | 崩溃前后恢复草稿完整；基版本落后、损坏/未来 schema 不覆盖现有正文；失败水位和待处理草稿可见 |
| A7 | 镜像失败不回滚成功 Commit；重启重放幂等；乱序任务不回写旧版本；外部修改后不被后台静默覆盖 |
| A8 | 只读目录、磁盘/队列满、文件替换/增长、路径逃逸、超限/非法编码均保持源文件与权威状态可解释 |
| A9 | 正常图形会话中文输入、撤销/重做、主题、焦点、Retry、文稿切换、退出重开有实际结果；创建失败不丢未保存草稿 |
| A10 | 无个人 patch 的已发布共享依赖组合通过 locked 全目标构建、核心/属性/协议/Web/产物检查；新增回归在最终源码 CI 真正执行 |
| A11 | 100/1000/5000 块语料下输入/flush/后台写入有限等待、UI 无同步文件 IO；与现有基线对比，无解释不清的明显回退；真实 IPC/paint 单列 |
| A12 | schema/备份恢复策略与实际路径文档齐全；明确只读降级、恢复候选和未完成后续能力；不把 W1 声称为 W2–W5 完成 |

确定性乱序用 oneshot/barrier，崩溃用真实子进程 failpoint；不以 sleep 猜执行顺序，不用仅调用 setter 的测试代替产品路由。旧创建/同步/增量回归继续保留。

## 9. 后续阶段进入与退出条件

- **W2：** 以 W1 持久化文稿为输入。Source/Live 切换共用同一正文/撤销语义；大纲和搜索由当前版本派生。章节排序与标题/路径更名各有事务和镜像更新策略，不能靠文件名字典序充当唯一顺序。跨章节搜索结果绑定文档版本，点击定位不误落旧位置。
- **W3：** 优先一个“选中段落 → 请求改写 → 看候选 → 接受/拒绝 → 定位/撤销”的完整切片；上下文绑定 store/document/version/block/selection。迟到结果与人工并发冲突不能直接 Apply；Agent 接受产生正常 Commit。真实模型调用、候选取消/失败/超时、同文档继续输入及一次撤销均有验收；StandIn 仅留自检。复用文本合并 spike 前先迁入生产纯模块和测试，不能依赖可删除 spike。
- **W4：** 首先交付图片导入/粘贴到稳定资源引用、caption/alt/来源编辑与重开恢复；资源落盘和正文引用需可恢复协调，删除/替换不能产生失联引用。书籍约束/术语/摘要各声明权威与派生关系；生成图片、完整文献管理另列子批次。
- **W5：** Prose Diff 先覆盖文字增删与段落移动；导出绑定稳定 revision，附字体/图片/脚注/引用等支持子集与损失报告。每种格式单独提供样例、视觉/结构验证和失败处理，不能用“能生成文件”替代验收。Markdown 镜像不等于全部出版导出已完成。

## 10. 完成定义

W1 满足 A1–A12 后，才将其状态改为已完成。实机、远端 CI、性能样本缺失分别标注，不归并成“开发完成”。W1 的存储事务和外部冲突属于功能必需项，不以 GUI 权限不足为由跳过实现。

后续详细设计可以随真实使用收窄，但需要更新本阶段索引及完成条件。暂不建设共享 Core 仓库、完整工作流内核、全格式转换引擎或跨产品数据库；实际功能证明需要时另立范围明确的任务。
