# 面板功能开发前的最小稳定化收口 Spec

- 日期：2026-11-05
- 状态：部分实施。A1–A3 已验证；A4 仅本地提交（未推送 / 未跑远端 CI）；A5 实机冒烟被 GUI 权限阻断；本文不把未执行项视为通过。
- 配套计划：[Implementation Plan](../plans/2026-11-05-panel-development-readiness.md)
- 范围：Digger 用量面板的异步作用域隔离、Dozer / Digger 最新代码的可复现验证、两产品最小实机冒烟

## 1. 目标与退出条件

建立一个能继续叠加面板功能的可信基线：当前项目的数据不会被旧查询污染；最新产品源码可以使用已发布共享依赖构建和测试；真实输入、保存恢复、会话恢复与退出没有已知阻断。

本批完成后，以面板功能为主要开发工作，相关回归和实机验证随功能推进。首次复盘时间盒为 2–3 个工作日，时间盒不代替验收。发现数据丢失、崩溃、输入阻断、无法回收的受管进程或项目数据串用时，先修复对应问题，再判断是否转入功能开发。

不纳入本批：通用面板框架、插件总线、编辑器底层替换、全量结构重构、完整历史二进制兼容矩阵、完整多屏故障矩阵与端到端性能工程。新的共享版本仅在现有已发布版本确实无法承载修复时考虑。

### 2.1 用量旧回包：待确定性复现的静态发现

入口：`crates/desktop/src/adapters/usage.rs` 的 `set_scope`、`reset`、`activate`、`update`，以及 `product.rs` 的 `sync_usage_scope` / `Msg::Usage`。

- `set_scope` 只换路径，没有使旧查询失效。
- `reset` 重建共享 `WorkspaceState`，其内部 `refresh_generation` 归零。
- 查询使用固定 `project_id = 1`；当前结果直接进入共享 `update`。
- 共享库只比较刷新代数，无法表达 Digger 单槽面板跨项目、关闭后重开的生命周期。

推导场景：A 项目查询未完成 → 关闭所有项目并 reset → A 结果迟到；或关闭后打开 B，旧 A 的代数与新 B 相等 / 更大。旧结果可能被接收。当前仅完成静态检查，必须先通过可控 fake 服务复现，不能把本段写成实测故障。

## 3. 用量作用域隔离设计

### 3.1 所有权与接缝

| 层 | 负责 |
|---|---|
| ProductShell | 当前项目选择、可见性、作用域切换和消息路由 |
| Digger UsagePanel | 作用域生命周期、后台回包身份、过滤和展示数据清理 |
| dozer-panel-usage | 同一作用域内的刷新代数、聚合、筛选与共享视图 |
| dozer-client / daemon | 按项目路径查询会话用量，保持现有口径 |

优先在 Digger 宿主适配层修复，保持 `UsageService`、共享面板 Message 和 daemon 协议兼容。不得将用量改回应用操作账本或增加持久化迁移。

### 3.2 生命周期标识与后台消息

- UsagePanel 持有独立于 `WorkspaceState` 的 scope epoch。仅当前生命周期有效，清空展示状态不能重置 / 复用 epoch；使用 checked 递增，耗尽时明确失败并拒绝新查询，不能回绕。
- 作用域从 A 变 B、A 变 None、None 变 A 时，先使旧 epoch 失效，再清空旧数据、loading、筛选和通知。即使面板隐藏，也立即完成失效；相同作用域的重复同步保持幂等。
- `activate` 捕获当前 scope 和 epoch，通过适配层结果信封回传共享 Message。接收端在进入共享 `update` 前检查当前 scope 非空、epoch 与 scope 均匹配。
- 同一作用域内多次 activate 继续依赖共享刷新代数，后发查询优先；scope epoch 负责跨生命周期隔离，两者不能互相替代。
- 后台结果使用带身份的专用入口，用户筛选 / 折叠等交互保持原路由。禁止保留一条可绕过身份检查的后台 `Loaded` / `LoadFailed` 产品入口；现有 selftest / fixture 随接缝调整。
- 旧成功和旧失败一律丢弃，不能改动 rows、loading、Git 统计、筛选、错误提示或原生展示。关闭所有项目后保持空态且不发查询。
- 清空旧数据后同步原生 Usage 视图；不能只清 Rust 状态、让 webview 继续显示旧项目图表。

本批不要求服务端强制取消查询；正确性由消费端身份检查保证。若现有任务能安全取消可复用，但取消不能替代旧回包过滤。

### 3.3 确定性行为测试

用 fake `UsageService` 和 oneshot / barrier 控制完成顺序，使用有限超时作失败保护，不以 sleep 猜调度时序。至少覆盖：

1. 无项目不查询；A 查询发出后关闭所有项目，A 成功迟到仍为空。
2. 同一路径 A 关闭再打开，旧 A 结果不能覆盖新 A；epoch 不因 reset 复用。
3. A → B，B 先成功、A 后成功，最终只有 B。
4. A → B，旧 A 失败不产生 B 的错误 / notice，也不结束 B 的 loading。
5. 面板隐藏时 A → B，A 回包不能保留旧数据；再次显示只查询并展示 B。
6. 同一作用域两次刷新乱序，保留最新结果；相同 scope 同步不无故清空当前数据。
7. 关闭、切换时原生展示收到清空 / 刷新；通过真实 ProductShell 消息路径验证旧后台消息被拒绝。

## 4. 可复现基线与 CI

最终检查须绑定 Dozer / Digger 的确切源码 SHA、锁文件摘要、工具链、共享依赖 tag / SHA 与 CI URL。两产品是一个明确版本组合，不要求所有仓库都发新版本。

- 在可写临时副本、独立且无 patch 的 Cargo 配置下验证；配置来源、工作目录和依赖解析结果可核对。不得仅因源码副本没有 `.cargo` 就假设全局配置无覆盖。
- 发布依赖使用 bytehost v0.4.23、byteui v0.5.2、bytegit v0.9.2 与 Digger 所需 Dozer 已发布 libs 快照；执行时核对真实 tag / SHA。
- 先验证预备提交内容，再在隔离副本明确生成正式锁；随后所有检查使用 `--locked`。记录锁差异原因，禁止检查过程隐式改写开发者锁。
- 检查依赖图每个共享包只有一个来源，正式锁不含 sibling path 来源。
- 跑两产品 workspace all-targets check、相关行为测试、已有边界 / 依赖门禁；把新用量生命周期回归纳入 Digger PR 快速集。
- Digger 全量 desktop lib 验证前构建 scale probe。默认并行运行必须有限时间结束；既有 agent_hooks 抖动需保留失败日志并定向 / 串行确认，不跳过断言伪造全绿。
- 最终源码提交的远端 CI 必须有结果；旧提交绿灯、仅修改 workflow 文件、共享库联合构建均不能代替两个产品最终提交的检查。

## 5. 最小实机冒烟

使用最终候选构建和两产品各自的临时数据根，记录 GUI、daemon 路径及构建身份。保留既有真实 daemon、用户配置和凭据；会话测试优先用 shell，真实 agent 所需配置写入另列并先明确范围。每次操作有观察窗口和超时，清理仅针对本次拥有的实例。

| 编号 | 产品与操作 | 必须观察到的结果 |
|---|---|---|
| M1 | 两产品打开 / 关闭 / 重开设置；父窗 resize；设置前后台切换 | 无孤儿遮罩、层级错乱、主窗输入阻断；可关闭并重新打开 |
| M2 | 两产品设置中可输入字段进行中文组字、Esc、复制粘贴；内层确认打开时按 Esc | Esc 先结束组合 / 取消内层确认，空闲时才关设置；焦点正常恢复；无真实 Token 留档 |
| M3 | 两产品 shell 会话持续输出、中文输入、resize；关闭 GUI 后重开；显式结束会话 | 可继续交互、恢复内容可解释，无串项目；GUI 关闭保留 daemon 会话与显式结束会话的语义分别验证 |
| M4 | Digger 编辑中文、多行、undo/redo、保存、退出重开 | 内容与保存结果一致；焦点和输入法正常；失败不会冒充保存成功 |
| M5 | Digger A/B 项目用量切换、关闭全部、关闭再开 | 当前项目口径正确；空态无旧图表；慢回包的确定性保证由 §3.3 自动测试提供 |
| M6 | 两产品正常退出与测试实例清理 | 按现有 GUI / daemon 生命周期语义退出；本次要求停止的会话、进程和 socket 可回收 |

原生创建失败 / Retry 已有自动回归，实机有现成故障注入入口时补测；没有入口时登记未验，不为造故障扩写通用注入框架。多屏、Space / 全屏完整矩阵及历史兼容留在后续发行清单，不据此扩大本批范围。
